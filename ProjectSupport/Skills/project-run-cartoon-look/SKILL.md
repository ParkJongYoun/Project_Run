# Project Run 카툰 외형 적용

사용자가 2026-10-17에 좋아한 미노 외형을 기본 방향으로 사용한다. 다른 채팅에서도 이 파일과 참조 문서로 작업을 이어간다. 프로젝트의 정본이며 개인 스킬 폴더의 동명 스킬은 이 문서로 연결한다.

현재 6종은 사용자 추가 요청으로 [독립 카툰 에셋](references/independent-assets.md)으로 분리됐다. 해당 6종은 이 전용 프리팹과 리소스를 수정한다. 새 경기장에는 원본 외형 목록과 비교 토글이 없으며 이를 자동으로 다시 붙이지 않는다.

## 요청 해석과 기본 범위

- Project Run에서 “카툰풍으로 바꿔줘”라고 하면 **원본 UV를 유지한 알베도 재편집 + 승인된 셰이더·재질 + 가는 윤곽선 + 대상 화면에 필요한 조명 보정**을 적용한다. 색면을 정리하고 텍스처에 그려진 강한 명암을 줄여 셰이더가 입체감을 만든다.
- 최신 요청에서 대상과 스타일을 지정하면 그 내용을 우선한다. 대화·선택 객체·에셋으로 대상이 확인되면 바로 진행한다. 여러 대상 중 선택 근거가 없을 때만 대상 식별에 필요한 질문을 한다.
- 카툰 캐릭터는 **원본과 별개의 Regular 프리팹**으로 만든다. 원본 프리팹의 Variant나 씬 재질 오버라이드만으로 끝내지 않는다. **새 카툰 전용 재질과 텍스처**를 만들고 원본 캐릭터의 기존 재질을 연결하거나 수정하지 않는다. 메시·아바타·애니메이션도 카툰 전용 리소스로 복제하며, 검증된 카툰 공용 셰이더·이펙트만 공유할 수 있다. 기존 카툰 결과를 다듬을 때는 해당 독립 에셋을 수정한다.
- 탈것을 경기 주자로 가져올 때는 원본 탈것 모델과 애니메이션을 재사용하되, 카툰 프리팹에서 기수 객체·Animator·탑승 클립·기수 얼굴 참조를 제외한다. 초상화·이름·클로즈업은 몬스터에 연결한다. 원본 기수 및 탈것 에셋은 보존한다.
- 모델링·UV·리깅·애니메이션·스탯·이동속도·크기·무기 표시 변경은 별도 요청 범위다. 기존 미노의 무기 제거와 크기 보정은 이전 합의이며 다른 모델에 자동 적용하지 않는다.
- 타이틀 버튼, 빌드 씬 등록, UI·초상화 교체는 요청한 연결 범위에서 처리한다. 단순 외형 변경 때문에 프로젝트 전체 씬·품질·화면 방향을 바꾸지 않는다.
- 명시적인 적용 요청은 실행 권한이다. 별도 시안 승인을 반복해서 요구하지 않는다.

## 시작 전에 읽을 것

1. 저장소 루트 `AGENTS.md`와 `Run/DataBundles/기획/Project_Run_개발_규칙.md`를 읽는다. 현재 체크아웃을 사용하며 기본 위치는 `D:/Project_Run`이다.
2. [승인된 외형과 수치](references/approved-look.md)를 읽고 실제 씬·재질을 확인한다. 기존 결과는 재사용하고 없는 대상만 새로 만든다.
3. 텍스처 편집 시 현재 제공되는 `imagegen` 스킬과 [UV 텍스처 프롬프트](references/texture-prompts.md)를 읽는다. Unity 조작 시 `unity-mcp-orchestrator`를 따른다. UI 작업이 추가될 때만 해당 UI 스킬을 사용한다.

## 작업 순서

### 1. 대상과 원본 연결 조사

- 원본 모델, 텍스처, Renderer별 `sharedMaterials` 슬롯, UV/알파 사용, 윤곽선 메시, 현재 씬에서 실제 적용되는 재질을 조사한다. 6종 예제가 슬롯 하나라고 새 모델도 하나로 가정하지 않는다.
- 수정 전 대상 에셋·원본의 경로와 해시, 관련 스크립트와 씬 변경 상태를 기록한다. 다른 작업의 미커밋 변경은 유지한다.
- Unity를 사용할 때 현재 인스턴스 목록에서 프로젝트 경로가 `D:/Project_Run/Run`인 인스턴스를 명시적으로 선택한다. 세션 ID는 매번 조회한다. 여러 Editor가 있으면 자동으로 Run에 연결된다고 가정하지 않는다.
- 다른 채팅이 같은 Editor를 조작 중이면 사용 종료를 확인한 뒤 씬을 바꾼다. 저장하지 않은 다른 작업을 버리거나 임의로 저장하지 않는다. 파일 조사·프롬프트 준비는 그동안 진행할 수 있다.

### 2. 알베도 편집

- 원본 이미지를 먼저 직접 확인한다. 승인 예시의 출력도 필요하면 함께 확인한다.
- 이미지 편집 도구에 실제 원본 atlas를 전달하고 텍스처별로 한 장씩 편집한다. 현재 기본 도구는 built-in `image_gen`; 설치 경로나 생성 폴더를 하드코딩하지 않는다.
- UV 섬과 눈·입·무늬의 정규화 좌표, 실루엣·방향·여백·알파를 보존한다. 강한 baked shadow/highlight와 잔털·붓질 노이즈를 줄이고 캐릭터의 고유 색과 표정은 유지한다.
- 생성 결과를 `Run/Assets/ArtBundles`의 대상별 폴더로 복사한다. 원본에 덮어쓰거나 임시 생성 폴더에 Unity 참조를 남기지 않는다.
- 실제 출력 크기·알파를 확인한다. 요청 크기가 생성 파일 크기와 같다고 보고하지 않는다. 임포트 해상도는 파일 해상도와 별도로 기록한다.
- atlas만 보고 성공 처리하지 않는다. 실제 모델에 연결한 후 눈·입 위치, UV 경계와 늘어짐을 확인하고 잘못된 결과는 재편집한다.

### 3. 재질과 윤곽선 적용

- `Assets/ArtBundles/Characters/CartoonMonsters` 아래의 승인된 카툰 재질을 대상 전용 재질로 복제한다. 공용 셰이더는 `ProjectRun/CartoonMonsters/MonsterAnime`을 사용하며 미노는 독립 카툰 폴더의 전용 셰이더·재질을 유지한다. 원본 외형용 `ProjectRun/MonsterAnime` 재질을 직접 연결하지 않는다. 캐릭터별 차이는 새 재질에서 보정한다.
- [수치 표](references/approved-look.md)의 값으로 시작해 털·피부·금속·밝은 색의 가독성을 맞춘다. 원래 슬롯 배열과 `_Cull`, `_AlphaClip`, `_Cutoff`, UV tiling/offset의 의미를 보존한다.
- 기존 outline renderer가 있으면 독립 프리팹 안에서 재사용한다. 없으면 대상 메시·스키닝·노멀에 맞게 구성한 뒤 `ProjectRun/CartoonMonsters/MonsterOutline` 셰이더를 사용하는 새 윤곽선 재질을 연결한다. 재질 할당만으로 윤곽선 메시가 생기지는 않는다.
- 비교 전용 요청에서만 `Sys_RaceLookDev`의 재질 매핑을 활용한다. `Use Updated Look`은 **텍스처를 포함한 표면 재질·셰이더·윤곽선**을 교체한다. 조명·환경·메시·경기 계산은 이 토글로 되돌아가지 않는다. 현재 독립 카툰 6종에는 사용하지 않는다.
- 실행 중 원래 재질로 돌아간다면 `Sys_MonsterLook`과 `Sys_RaceRenderStyle` 등 실제 쓰기 경로를 확인한다. 충돌하는 스타일 제어만 대상 씬에서 정리하고 비교 버튼도 함께 맞춘다.

### 4. 씬·조명과 게임 연결

- 기존 밝은 키 라이트, 차가운 필 라이트, 따뜻한 림 라이트와 차분한 환경색을 출발점으로 삼는다. 기존 승인 씬에서는 중복 조명·Volume을 추가하지 않는다.
- 조명·환경 보정이 필요한 대상 씬에만 적용하고 독립 재질·Volume 프로필로 다른 씬의 외형을 보존한다. 카메라 거리별 초점과 여러 주자의 선명도를 확인한다.
- `PC`/`PC_RPAsset` 품질을 유지한다. 성능을 이유로 임의로 품질이나 렌더링 해상도를 낮추지 않는다.
- 정적인 전시와 실제 레이스의 애니메이션 제어를 분리한다. 레이스에서는 `RaceRunnerView`를 유지하며 `Sys_MinorousLookDev.PlayIdleAnimation`은 false로 하여 두 PlayableGraph가 경합하지 않게 한다.
- 현재 `MonsterRaceLookDevBuilder.Build()`는 특정 6종과 새 씬 생성용이다. 기존 씬이 있으면 실패하도록 설계되어 있다. 새 모델용 범용 명령으로 실행하거나 기존 결과를 지우고 재실행하지 않는다. 필요한 부분을 읽고 대상에 맞춰 적용한다.

### 5. 검증과 기록

- 같은 카메라·조명에서 원본/수정본을 비교하고 근접 정면·측면·후면, 경기 중 원거리 구도에서 UV 경계·얼굴·윤곽선·과한 광택·흐림을 점검한다.
- 셰이더 컴파일과 Unity 콘솔을 확인한다. 신규/수정 재질이 실제 Renderer와 모든 필요한 슬롯에 적용됐는지 확인한다.
- Regular 프리팹 여부와 재귀 의존성을 검사해 원본 프리팹·원본 재질·원본 텍스처가 남지 않았는지 확인한다. 표면·윤곽선·비활성 Renderer·스타일 제어기의 재질 배열도 포함한다. 원본을 상속하거나 런타임에 기존 재질로 되돌리는 연결은 제거한다.
- 레이스에 연결했다면 출발·이동·스킬·완주·결과·다시 달리기에서 외형이 유지되는지 확인한다. 경기 흐름/건너뛰기 코드를 바꾼 경우 자연 완주와 건너뛰기의 결과 일치도 검사한다.
- 초상화를 만들었다면 유효한 포즈를 샘플링한 복제 모델과 실제 메시 경계로 촬영하고 빈 이미지·잘림을 확인한다. 실주행 모델의 포즈를 촬영용으로 바꾸지 않는다.
- 작업 전후 원본 해시와 변경 파일을 비교한다. 원복 방법을 남긴다. 공유 셰이더·재질·프로필을 수정했다면 참조하는 다른 대상도 확인한다.
- `Run/DataBundles/LookDev/<대상_날짜>/`에 원본·출력·씬 경로, 최종 프롬프트, 생성 도구, 해시, 실제 파일/임포트 크기, 재질 차이, 비교 화면과 검증 결과를 기록한다.
- 실제 수행한 검증만 완료로 보고한다. Editor 검증, 빌드 등록, 실제 WebGL 브라우저·모바일 성능 검증은 구분한다.
