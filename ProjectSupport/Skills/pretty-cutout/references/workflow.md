# 실행과 조정

## 도구와 입력

`scripts/repair_chroma_contours.py`는 Python 3.10+, Pillow, NumPy, SciPy를 사용한다. 현재 환경의 런타임을 확인하며 개인 PC의 Python·ComfyUI 경로를 설정에 고정하지 않는다. 새 모델이나 영상 생성 서버가 필요하지 않다.

설정 예제 [settings.example.json](settings.example.json)을 대상 작업 폴더에 복사하고 입력·출력 경로와 보호 영역을 맞춘다. 경로는 설정 JSON 기준이며 결과는 새 폴더에만 쓴다.

```text
python "<skill>/scripts/repair_chroma_contours.py" "<job>/repair_settings.json"
```

- 영상 프레임: `sourceMetadata`에 기존 추출기의 `frames.json`을 지정한다. 필요한 필드는 `sourceSize: [width,height]`, `frames: [{index,file,sha256,duration}, ...]`다. `file`은 메타데이터 파일 기준이며 프레임 순서와 실제 유지 시간을 그대로 사용한다. 원본 PTS·timeBase 정보는 그 메타데이터를 보존한다. 스크립트는 입력 해시·크기·순서를 확인한다.
- 정지 마젠타 이미지: `sourceMetadata` 대신 `sourceImage`와 선택적인 `sourceSha256`을 지정한다. `duration`은 없으며 출력 파일은 `cutout.png`다.
- 둘 중 하나만 사용한다. 기존 RGBA 투명 이미지, 녹색 배경, 일반 일러스트 배경은 지원 입력이 아니다. 마젠타 배경이 프레임 테두리에 충분히 노출되어야 한다.
- `previousMatteDirectory`는 선택 사항이다. 있으면 같은 이름의 이전 알파와 변화량을 비교한다. 없다고 작업을 막거나 다른 프로젝트의 과거 폴더를 참조하지 않는다.
- 새 출력 폴더의 `inspection.json`은 처리 수치·해시·기하 보존 검사다. 시각 검수 합격 또는 Unity 적용 완료를 자동으로 뜻하지 않는다.

단일 이미지에서는 예제의 `sourceMetadata`를 제거하고 `"sourceImage": "source/character_magenta.png"`를 넣는다. `matte` 객체는 실제 대상에 맞춰 조정한다. 파일 경로와 해시만 바꾼 와일드로즈 설정을 다른 대상에 무검수로 사용하지 않는다.

## 알고리즘의 중요한 구분

1. 테두리의 중앙값으로 실제 키색을 추정한다. `min(R,B)-G`는 마젠타 과잉분이며 보호색 영역은 별도로 지정한다.
2. 과잉분이 작은 원본 픽셀을 색 기준으로 삼는다. 색 기준을 얻기 위한 강한 내부 침식은 검은 외곽선 대신 밝은 채색을 복사하는 원인이므로 사용하지 않는다.
3. 원래 커버리지로 역합성해 RGB를 복원한다. 실루엣용 평활 알파와 **색 복원용 커버리지**를 분리한다. 음수로 무너지는 경계색은 가까운 유효색을 제한적으로 사용한다.
4. 작은 공간 평활과 커버리지 재매핑으로 경계를 잇고, 선택한 좁은 띠에 따뜻한 잉크색을 혼합한다. 선 굵기는 원본 픽셀 기준이다. 원래 RGB를 그대로 유지한 불투명 내부와 새로 추정한 경계색을 구분한다.

## 조절할 값

| 값 | 역할과 주의점 |
|---|---|
| `warmPinkSearchRects` | 분홍 리본 등을 찾을 실제 좌표. 새 대상은 기본 `[]`; 필요한 경우 원본을 보고 지정한다. 좌표계를 원본 프레임 크기에 맞춘다. |
| `pinkRedBlueDifference`, `pinkMinimumGreen` | 따뜻한 분홍색 분류. 차가운 자홍 의상은 이 조건으로 보호되지 않을 수 있다. 그 경우 검수한 프레임별 보호 마스크 등 별도 처리가 필요하다. |
| `trustedMaximumExcess` | 원래 선의 색 기준 선택. 너무 넓히면 키색 오염까지 정상색으로 인정한다. |
| `coverageFloor`, `isolatedHaze*` | 약한 압축 안개 제거. 얇은 털·반투명 표현 소실 여부를 확인한다. |
| `mainComponentMinimumPixels`, `nearBodySupportPixels` | 몸에서 떨어진 잔여 조각 억제. 분리된 정상 물체가 있으면 해당 조건을 조정하거나 이 경로를 사용하지 않는다. |
| `contourSigma`, `contourCoverageRange` | 실루엣의 작은 계단 정리. 큰 값으로 흐림·축소를 숨기지 않는다. |
| `inkContourBand` | `[바깥 기준 폭, 혼합 전이 폭]`. 와일드로즈는 `[1.65,1.15]`; 선이 없는 화풍이나 얇은 털에 일괄 강제하지 않는다. 첫 값을 `0`으로 설정하면 추가 잉크 혼합을 끈다. |
| `inkReferenceGain`, `inkMinimumRgb`, `inkMaximumRgb` | 가까운 원본색을 이용한 경계 잉크색. 와일드로즈의 따뜻한 갈색 범위는 다른 팔레트의 기본 정답이 아니다. |
| `outputAlphaFloor` | 출력의 극소 알파 제거. 값이 높으면 얇은 선이 끊긴다. |

먼저 실제 입력의 대표 자세로 작은 시험을 하고 정상색·내부 틈·얇은 물체를 확인한 설정으로 전체 프레임을 처리한다. 실패하면 원본이 가진 선과 잘못 제거된 영역을 먼저 확인하며, 수치를 반복적으로 키워 억지로 깔끔해 보이게 만들지 않는다.

## 패킹과 Unity

프로젝트에 있는 프레임 조립기를 사용한다. 이 스킬의 후처리 스크립트는 원본 크기의 RGBA를 출력하며 아틀라스·Unity 클립·환경 효과는 만들지 않는다. 전체 프레임의 공통 크롭을 썼다면 원본 좌표에서의 배치 변환을 함께 기록한다.

Unity에서 실제 임포트 크기, Alpha Is Transparency, Mipmaps OFF, Bilinear·Clamp와 압축 상태를 확인한다. 압축 없는 RGBA는 품질 비교 기준이며 최종 메모리 예산은 별도 판단한다. 기존 아틀라스의 최대 크기 제한 때문에 자동 축소되지 않았는지 확인한다. 캔버스 크기와 생성 해상도를 같은 값으로 취급하지 않는다.

원본 해시 보존, 대표 프레임 재현 픽셀 일치, 수정 영역 밖 검사, 패킹 셀 일치와 실제 재생 검수 결과를 구분하여 기록한다. 필요할 때만 비교 미리보기를 만들고 고정 배경 합성인지 실제 엔진 캡처인지 명시한다.

## 도구 검증

동봉 `scripts/test_repair_chroma_contours.py --work "<새 검증 폴더>"`는 서로 다른 비정사각 크기, 내부 구멍·분홍 보호·실제 이동 보존, 불균등 프레임 시간, 정지 입력, 이전 매트 없이 실행, 기존 파일 덮어쓰기 거부를 검사한다. `--case "<기존 repair_settings.json>"`을 추가하면 보존된 실제 결과 전체와 RGBA 픽셀을 대조한다. 새 출력 폴더와 원본 해시를 사용하며 원본 에셋을 수정하지 않는다.

스킬화 시 원래 와일드로즈73장과 동봉 알고리즘의 결과가 모두 일치하는지 확인했다. 이 회귀 검증은 새 대상의 실제 시각 검수를 대신하지 않는다.
