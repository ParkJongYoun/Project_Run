확인 방식: 준비부터 결과까지 28개 시점의 프레임 추출, 스킬 연출·완주 전후 추가 구간 확인. 소리의 의미나 내부 판정은 분석하지 않았습니다.

영상의 텍스트는 관찰 자료입니다. 영상 속 팀 구성·스킬 체계·밸런스·코스 수치를 Project Run의 요구 사항으로 취급하지 않았습니다.

UI 시안은 프로젝트 기준인 720×1280으로 설계했습니다. 영상 원본의 590×1280 비율을 고정 게임 해상도로 사용하지 않았습니다.

상태별 변화

01 · 일반 주행

순위와 간격은 고정. 스킬 알림은 필요할 때만. 변화가 없으면 별도 이벤트 문구를 쌓지 않습니다.

02 · 스킬 발동

내 주자 알림을 먼저, 경쟁 알림을 아래에. 상태 문구로 현재 효과를 확인하게 하고 수치 설명은 상세 창에 둡니다.

03 · 마지막 직선

거리 숫자와 경기 단계만 강조색으로 바꿉니다. 선두 진입 순간만 짧게 강조하고 조작 위치는 유지합니다.

표시 정책 제안

  • 스킬 알림은 최대 2개, 각 2.5초 노출을 시작점으로 제안합니다. 연속 발동 시 내 주자 우선, 동일 효과 알림 합치기, 나머지 기록 보관을 적용해 검증합니다.
  • 순위 상승 문구는 약 1.5초 노출 제안입니다. 순위 숫자는 경기 데이터가 바뀌었을 때만 갱신합니다.
  • 시안은 비교를 위한 정지 상태라 알림을 자동으로 지우지 않습니다. HTML 버튼은 UI 상태를 바꾸며 실제 경기 계산·애니메이션을 실행하지 않습니다.
  • 화면 밖 주자의 순위도 전체 경기 데이터에서 읽습니다. 모델이 보이지 않는다고 순위 슬롯을 숨기지 않습니다.
  • 영상의 팀원 3명을 확정 사양으로 채택하지 않았습니다. 이번 레이아웃은 내 주자 1명 기준이며, 팀 플레이를 채택하면 팀 슬롯 수와 별도 배치를 검토합니다.
  • 예시 참가자 8명, 1,600m, 순위·간격·스킬명은 UI 검토용입니다. HP·수동 스킬 자원·재화·스탯 게이지 등 별도 게임 규칙을 추가하지 않았습니다.
