2. 화면 설계
레퍼런스: ../레퍼런스/우마무스메의 정면 대열, 측면 추적, 공식 레이스 및 스킬 화면과 기존 영상 분석 문서.
상단 진행도 / 중앙 주행 장면 / 하단 순위·중계·관전 조작의 역할을 적용했다.
캐릭터는 탈것에 탑승한다. 현재 대표 조합은 기사 + 페코페코, 경쟁자에 포링과 말 등의 탈것을 배치했다.
청록색은 경기·조작, 아이보리는 읽기 영역, 골드는 내 주자·주요 순위·기록에 사용한다.
진행도는 내 주자의 이동 거리 1,180 / 1,600 m = 73.75%를 나타낸다.
번호 원형 목록은 순위 순서다. 원형 사이의 간격이 실제 주자 간 거리를 나타내지 않는다.
최종 코너 상태에서 내 주자 03은 2위이며, 결과 예시는 역전 우승이다.
주자 얼굴과 탈것 머리·발을 중앙 경기 영역에서 최대한 가리지 않게 배치했다.
레이스에는 수동 스킬 버튼 대신 발동 알림을 제안했다. 이는 확정 경기 규칙이 아니다.
팀 인원을 확정하지 않고 내 주자 1명의 상태를 표현했다. 참가자 8명, 능력치, 적성, 교감, 스킬, 보상과 이름은 전부 화면 검토용 예시다.

3. Unity 적용
이 작업은 시안 제작이다. Unity 씬·C#·프리팹을 수정하거나 임포트하지 않았다.
실제 존재하는 D:/Project_Run/Run을 작업 대상으로 사용했다. AGENTS.md에 기재된 C:/Project_Run/Run은 이 환경에 존재하지 않았으며 지침 파일은 변경하지 않았다.
프로젝트 개발 규칙 1~15를 우선하고, 신규 UI는 UICanvas_Root 아래 지정 레이어에 둔다.
CanvasScaler: Scale With Screen Size / Reference Resolution 720×1280. 세로 화면 가로 폭 기준 유지 시 Match 0을 제안하며 실제 기기에서 검증한다.
RaceHUD는 Game(100), 출전·결과는 Panel(200), 일시정지·설정은 Popup(400).
상단은 Safe Area 상단, 하단 정보·조작은 Safe Area 하단에 앵커한다. 중앙 경기 뷰가 남은 높이를 사용한다.
긴 화면의 실제 Unity 카메라는 캐릭터 크기를 유지하며 수직 시야를 늘려야 한다. HTML의 고정 배경 이미지 cover 동작은 카메라 구현이 아니며 긴 화면에서 아트 크기가 달라질 수 있다.
프로젝트 규칙에 따라 패널은 UIPanel_Base / Mgr_UI와 연결하고 OnClose에서 구독과 작업을 정리한다.
화면의 숫자·이름·문구를 TMP로 분리한다. 완성 PNG나 투명 HUD 전체를 한 장짜리 게임 UI로 사용하지 않는다.
UI 스프라이트는 필요한 것만 Assets/Resources/UI에, 패널과 슬롯은 규칙의 Resources/Prefabs/UI 경로에 등록한다.
스프라이트는 Border 값을 적용한 Image.Type=Sliced, 아이콘은 Image.Type=Simple로 쓴다. 9-slice는 모서리만 유지하므로 긴 세로 그라데이션까지 픽셀 단위로 일치하지는 않는다.
비상호작용 이미지와 TMP는 Raycast Target을 끈다. 버튼은 상태별 색 틴트와 입력을 연결한다.
일반: 기본 색 / 눌림: 밝기 0.94 / 비활성: 알파 0.5 제안. 포커스는 골드 테두리.
한국어 폰트: 미리보기는 OS 기본 글꼴만 참조한다. 런타임은 프로젝트에서 사용 가능한 배포 허용 폰트와 TMP 폰트 에셋을 준비한다.
생성 배경은 시안용이다. 게임에서는 경기 씬 카메라와 V_ 전시용 프리팹으로 교체한다.
내 주자 표식은 얼굴을 가리지 않게 월드 기준점 + 화면 내 위치 보정으로 처리한다. 시안의 CSS 위치를 그대로 월드 표식 구현에 쓰지 않는다.
배속·건너뛰기는 동일 경기 계산을 진행하고 결과를 받아야 한다. 이 시안의 결과 화면 전환은 실제 경기 계산을 하지 않는다.

4. 확인한 내용
Chrome headless로 3개 화면, 투명 오버레이, 720×1600 Safe Area 시안을 렌더링하고 시각 확인했다.
320×568, 360×640, 390×844, 720×1280 화면에서 가로 넘침이 없음을 확인했다.
관전 조작 버튼은 위 화면들에서 최소 약 44 CSS px 높이를 확보했다. 320px 폭에서는 추가 높이 보정을 적용한다.
배속 표시 변경, 자동 카메라/내 주자 추적 표시 변경, 스킬 알림 토글, 결과까지 이동, 전체 8명 순위, 준비↔레이스 전환을 확인했다.
콘솔 JavaScript 오류 없음. 팝업 키보드 포커스 순환과 Escape 닫기를 구현했다.
UI 장면을 확인하는 정적 프로토타입이다. 달리기 애니메이션·실시간 순위·실제 배속·카메라 전환·보상 지급·저장은 구현하지 않았다.
실제 Unity WebGL 빌드, 휴대폰 Safari/Chrome, 노치 인셋, 렌더링 성능, TMP 가독성 검증은 별도 적용 단계에서 필요하다.

5. 실행 및 재생성
미리보기: index.html 열기. 또는 이 폴더의 상위에서 node serve.cjs 실행 후 http://127.0.0.1:4178 접속.
렌더링: node render-ui.cjs
아이콘 / 9-slice / 비교 보드: node handoff/build-handoff.cjs
렌더 도구는 설치된 Chrome과 Codex 번들의 Playwright를 사용한다. 다른 환경에서는 CODEX_NODE_MODULES 및 Chrome 경로를 변경한다.
