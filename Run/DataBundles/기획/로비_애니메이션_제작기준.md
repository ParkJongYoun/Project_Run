원본 프레임 격자는 `17k+5`다.

```text
n = max(5, round(seconds * 24))
frames = n + (5 - n % 17) % 17
```

예를 들어 2초 설정은 56프레임·약 2.33초, 3초 설정은 73프레임·약 3.04초가 된다. 이는 기존 워크플로의 계산 예시이며 로비 길이 지정이 아니다. 저장된 MP4의 실제 크기·FPS·프레임 수·길이를 결과 기록에 사용한다.

## 3 두 방식 비교와 권장안

**H5 로비의 기본 방향으로 1번, 정적 배경과 움직이는 영역을 분리하는 방식을 권장한다.** 현재는 이 방향의 원화·분리 자료를 준비했다. 움직이는 영역을 작게 저장할 수 있으면 같은 배경을 모든 프레임에 반복 저장하는 비용을 줄일 수 있다. 최종 재생 구성은 합성 품질과 브라우저 측정 결과로 검증한다.

| 비교 | 1번 정적 배경 + 움직이는 묶음 | 2번 전체 장면 스프라이트 |
|---|---|---|
| 제작 | 깨끗한 배경, 경계 처리, 겹침 순서 준비 필요 | 완성 장면을 한 번에 영상화·추출하기 쉬움 |
| 시각적 일체감 | 접촉·그림자·반사·가려짐을 맞춰야 함 | 같은 영상에 포함돼 합성 작업이 적음. 생성 중 배경 흔들림은 검사 필요 |
| 메모리 | 움직이는 묶음의 저장 면적이 작을 때 유리 | 매 프레임 전체 면적을 저장하므로 부담이 커지기 쉬움 |
| 수정 | 한 요소의 속도·반복·교체를 독립 조정 가능 | 한 부분을 바꿀 때 전체 장면을 다시 처리할 수 있음 |
| 화면비 | 배경 확장과 요소 배치를 따로 대응 가능 | 전체 그림의 크롭·여백 정책 필요 |
| 적합한 경우 | 고정 카메라, 국소적인 일상 동작 | 화면 전체 움직임이나 광원·그림자 변화가 강하게 얽힌 장면 |

분리하더라도 캐릭터를 모두 따로 생성할 필요는 없다. 우로스와 도끼·장작, 고양이와 빗질하는 인물처럼 **서로 접촉하는 대상은 같은 영상 묶음**으로 만들어 동작을 맞춘다. 마타와 후경 주자는 독립된 묶음으로 구성하기 좋다.

원본 그림에서 움직일 대상을 지운 정적 배경이 필요하다. 원본 배경에 캐릭터를 남긴 채 움직이는 스프라이트만 겹치면 이전 자세가 뒤에 보인다. 움직임 전체를 포함하는 고정 영역과 기준점을 사용하고, 매 프레임 경계에 맞춰 중심을 바꾸지 않는다. 알파가 있어도 텍스처가 매번 전체 화면 크기라면 면적에 따른 메모리 절약은 거의 없다. 큰 레이어가 여러 장 겹치면 오히려 비용이 늘 수 있다.

전체 장면 방식의 “전체”는 배경·캐릭터 등 그림 영역을 뜻한다. 버튼·텍스트·가이드·설정 메뉴는 두 방식 모두 Unity UI로 별도 배치한다.

### 알파 처리 선택

사용자가 후속 답변에서 “캐릭터분리할거면 마젠타로 뽑아서 후처리까지”를 지정했다. 따라서 현재 분리 작업은 마젠타 방식으로 진행한다. 아래 다른 방법은 비교 기록으로 남긴다.

- **마젠타 생성 후 키 제거:** 단순한 배경에서 분리하기 좋지만 털·가느다란 선·분홍색 장식·그림자·연기는 별도 검수한다. 와일드 로즈의 분홍 리본은 보호가 필요한 후보다.
- **실제 배경이 있는 영상에서 마스크 추출:** 접촉 조명과 장면 분위기를 유지하기 쉽지만 프레임마다 경계와 가려짐을 추적해야 한다.
- **움직이는 영역에 주변 배경까지 포함한 패치:** 알파 작업을 줄일 수 있으나 고정 카메라와 안정된 배경이 필요하다. 테두리·색 변화·이중 배경이 보이면 다른 처리가 필요하다.

SGL 매트 시작값 `keepExcess=30`, `clearExcess=210`, `unmix=1.0`과 최대 3px 경계 보정을 이번 **정지 원화 시험에 적용**했다. 불투명 경계의 남은 마젠타도 최대 3px 범위에서 내부 색으로 보정했다. 와일드 로즈 리본과 후경 포링에는 보호 마스크를 적용했다. 이 값은 영상 전체에 검증된 최종값이 아니며, 생성 영상에서는 프레임별 보호 마스크와 경계 깜빡임을 다시 검수한다.

### 메모리 판단 기준

비압축 RGBA32의 픽셀 메모리는 대략 `가로 × 세로 × 4바이트 × 프레임 수`다. 예를 들어 **가상의 1280×720·73프레임**이면 한 장면 약 **256.6 MiB**, 세 장면을 모두 올리면 약 **769.9 MiB**다. 이 값은 출력 해상도 제안이나 실측이 아니며, 아틀라스 빈칸·패딩·밉맵·CPU 복사본 등의 추가 비용을 제외한 계산이다. 압축 형식에 따라 실제 메모리는 달라진다. [Unity 텍스처 형식 표](https://docs.unity.com/en-us/engine/6000.0/manual/materials-and-shaders/textures/textures-getting-started/texture-compression-formats/texture-formats-reference)

PNG 파일 용량과 GPU 메모리는 다르다. 지원하지 않는 GPU 압축 형식은 비압축으로 풀릴 수 있으므로 실제 브라우저의 형식과 메모리를 확인한다. [Unity GPU 압축 설명](https://docs.unity.com/en-us/engine/6000.7/manual/materials-and-shaders/textures/textures-getting-started/texture-compression-formats/fundamentals)

## 4 해상도 테스트와 기록

생성 해상도, 후처리 셀 크기, UI 설계 기준, 브라우저 렌더링 크기를 각각 기록한다. 현재는 해상도 후보도 확정하지 않는다. 같은 장면·동작·길이·시드·모델 조건에서 크기를 바꿔 비교하고, 선택 결과를 이 문서와 설정 기록에 함께 반영한다.

1. 장면 하나를 정하고 실제 로비 표시 크기에서 얼굴·털·도끼·손·배경의 선명도를 확인한다.
2. 원본 MP4의 전체 프레임·PTS·크기를 보존해 추출한다. 스프라이트 최종 프레임 선별과 유지 시간 편집은 그다음에 진행한다.
3. 두 방식의 합성 경계, 동작 연결, 루프 이음새를 비교한다. 역재생이나 교차 페이드만으로 자연스러운 반복이 확보됐다고 보지 않는다.
4. 아틀라스 실제 크기와 페이지 수를 기록한다. 텍스처 한도를 넘으면 여러 페이지를 검토하고 임포트 자동 축소로 맞추지 않는다.
5. 목표 모바일 브라우저에서 로딩, 메모리, 재생 프레임 시간, 메뉴 반응, 장면 전환 중 최대 사용량을 측정한다. 세 장면을 항상 모두 상주시킨다고 가정하지 않고 전환 중 현재·다음 장면이 겹치는 비용도 확인한다.

| 테스트 항목 | 기록할 값 |
|---|---|
| 환경 | 날짜, 기기, OS, 브라우저, Unity 빌드 |
| 생성 재현 | 입력 해시, 워크플로 해시, 프롬프트, 시드, 모델, 스텝, Turbo |
| 해상도 | 입력 크기, 요청 크기·비율·MP·배수, 실제 MP4 크기, 최종 셀 크기 |
| 시간 | 설정 초, 실제 FPS·프레임 수·초, 선별 프레임·유지 시간, 반복 구간 |
| 방식 | 배경 분리 / 전체 장면, 알파 방법, 움직이는 묶음의 범위·기준점 |
| 임포트 | 시트별 크기·페이지 수, 실제 GPU 형식, 압축, 밉맵, Read/Write |
| 결과 | 다운로드 용량, 최초 표시 시간, 메모리 최대값, 재생·전환 프레임 시간 |
| 시각 판정 | 선명도, 접촉·그림자, 배경 흔들림, 경계 번짐·깜빡임, 루프, 잘림 |
| 결정 | 채택·보류·재검토 사유와 최종 수치 |

SGL의 `800` 셀·발 기준점 `(400,600)`·피벗 `(0.5,0.25)`·5열 패킹은 캐릭터 전용 기준으로, 로비에 승계하지 않는다. SGL 문서의 Builder는 클립당 단일 PNG를 전제로 하므로 로비용 다중 페이지 재생을 지원한다고 가정하지 않는다. Project Run에도 `Tools/SpriteAnimation/prepare_video_animation.py`의 800셀 초안이 남아 있어 사용 전 조정이 필요하다.

현재 웹 기본 품질 `PC`·`PC_RPAsset`을 유지하고, 실제 시각 기준과 모바일 측정 없이 렌더링 해상도나 품질을 자동 하향하지 않는다. 제작 원본·기록은 `DataBundles`, 적용할 아트는 `Assets/ArtBundles`, 런타임 로드 대상은 `Assets/Resources` 기준을 따른다.

전 프레임에서 같은 896×646 영역을 정수 크롭해 원래 배경 좌표에 연결했다. 프레임별 재중앙 정렬이나 확대·축소는 하지 않았다. 아틀라스는 3600×3900 세 장과 900×650 한 장이며, 매트 후 RGBA와 저장된 각 셀의 픽셀 일치를 확인했다. 실제 Unity 임포트도 해당 크기의 RGBA32·FullRect·Bilinear·Clamp·밉맵 OFF·Read/Write OFF·최대4096이며 WebGL 강제 축소 override는 없다.

메이드의 빗질, 집사·고양이의 눈깜빡임, 꼬리 움직임은 생성 영상에서 온다. 커튼은 이미 잘라둔 256×448 패치의 천 내부만 최대1.5 원화 픽셀·주기5.4초로 움직이는 셰이더 보조 연출이다. 고양이 아래에는 첫 프레임의 밑면을 기준으로 부드러운 고정 접촉 그림자를 추가했다. 로비의 멈춤 버튼은 캐릭터와 커튼을 함께 정지한다.

1280×720 Unity Play에서 합성 화면, 모든73프레임, 10초 동안 네 번의 반복 전환, 멈춤 후 재생, 참조 누락0·Console 오류/경고0을 확인했다. 씬을 저장하고 Play는 종료했다. 머리카락 등 가는 경계에는 원본 영상 압축에 따른 미세한 부드러움이 남는다.

**이번 값은 화질 확인용 시험값이다.** 프레임 PNG 합계는34,286,891바이트이고, RGBA32 프레임 텍스처의 픽셀 저장량은170,820,000바이트(약162.91MiB)다. Unity Editor의 해당 텍스처 런타임 메모리 보고값은344,887,200바이트이며 모바일 브라우저 측정값이 아니다. 단일 장면에도 큰 편이므로 최종 규격은 실제 모바일에서 선명도·첫 로딩·메모리·재생 성능을 확인한 뒤 결정한다. 이번 작업은 웹 빌드·모바일 측정과 다른 두 장면의 생성까지 완료한 상태가 아니다.

## 8 v02 알파 경계와 환경 움직임 수정

사용자가 플레이 후 지적한 경계선과 약한 환경 움직임을 수정했다. 원본 ComfyUI 영상은 그대로 보존하고, 원본 RGB 73프레임에서 알파와 경계색을 다시 계산했다. 마젠타가 섞이지 않은 주변 전경색을 기준으로 반투명 경계의 색을 복원하고, 머리카락·옷 가장자리의 번짐과 팔 사이 좁은 틈의 잔여 마젠타를 정리했다. 분홍 리본은 프레임별 색 마스크로 보호한다. 전체 실루엣을 일괄 침식하는 방식은 사용하지 않았다.

재현 도구는 `Tools/SpriteAnimation/key_lobby_video.py`, 실제 설정은 [matte_settings.json](../LobbyAnimation/WildRose_v02/matte_settings.json), 적용 매트는 `WildRose_v02/matte_v2`다. 같은 좌표계를 유지한 고정 셀은 **899×648**이며 3612×3912 아틀라스 3장과 903×652 한 장에 원본 73프레임·PTS를 모두 유지한다. 임포트 크기와 RGBA32 형식을 확인했고, 원본 영상 해시와 매트→아틀라스 픽셀 일치 검증을 통과했다.

환경은 기존 작은 커튼 패치를 비활성화하고 **배경 전체에 영역별 마스크를 사용하는 셰이더**로 교체했다. 양쪽 커튼은 원화 기준 최대20px, 꽃다발은8px, 앞쪽 잎은14px의 가로 진폭을 사용한다. 1280×720 설계 화면에서는 각각 약15.3px·6.1px·10.7px에 해당하며, 실제 이동량은 마스크와 파형에 따라 달라진다. 창문·벽·침대는 움직임 영역에서 제외하고 마스크 가장자리를 부드럽게 연결했다. 별도 환경 영상을 생성한 작업은 아니다.

## 10 512 크기 대기·쓰다듬기 연결 검증

사용자는 긴 먹이기 반복 대신 짧은 대기를 주로 반복하고 특수 동작을 가끔 재생하는 구성을 요청했다. 1536×864 대기 생성은 사용자의 중지 요청으로 취소했으며 완성 영상이 없다. 이후 512 크기·3~5초 조건으로 **대기와 쓰다듬기 두 영상을 새로 생성**했다. 이번 범위는 개별 영상과 연결부 확인이며 게임에는 적용하지 않았다.

샘플 동작과 각 연결의 마지막4·처음4프레임을 확인했다. 쓰다듬기는 빗질과 고양이의 눈감음 후 원래 자세로 복귀한다. 대기는 사람·배경의 작은 움직임이 있으나 꼬리가 의도보다 크게 흔들린다. 전체 자세와 구도는 가까워도 인물·손 윤곽과 색감의 차이가 남는다. 따라서 **대기 반복, 대기→쓰다듬기, 쓰다듬기→대기를 매끄러운 연결로 채택하지 않았다**.
