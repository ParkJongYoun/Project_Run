Project Run 2D 레이스 야간 작업 보고 — 2026-10-16

완료
- Scene_2D_3D: 기존 3D 경기장 위에 탈것·탑승자 6종의 2D 이미지를 배치하고 실제 경기 위치로 이동한다. 사이드·후방·상공 구도에 맞춰 이미지를 바꾼다.
- Scene_All2D: 경기장 4구간 × 3뷰 배경, 구간 전환·스크롤과 6종 주자를 연결했다. 세 카메라 구도는 자동 전환되며 공통 카메라 버튼으로도 전환된다.
- 세 씬은 공통 UI와 경기 시뮬레이션·결과 규칙을 사용한다. 두 2D 씬에 기존 여우 필살기 영상을 연결했다.
- 원화 18장과 배경 12장의 원본을 보존했다. 원본 3D 씬 파일의 SHA256도 유지했다.
- 6종 × 3뷰 달리기 영상을 800×800·24fps·H3 fl2va UNet INT8·25steps·turbo OFF로 생성·검수했다. 2초 요청의 실제 원본은 56프레임, 약 2.333초다.
- 18개 뷰 중 16개를 투명 달리기 루프로 적용했다. 선택한 반복 구간은 약 0.5~1.25초이며 원본 전체 캔버스의 비율·좌표·피벗을 유지한다. 임의 프레임 확대·축소나 잘린 신체 보정은 하지 않았다.

미완료
- 멧돼지 사이드, 검은늑대 상공 달리기 루프: 반복 생성에서도 발 또는 꼬리가 프레임 경계에서 잘려 완전한 루프를 확보하지 못했다. 두 뷰는 원본 정지 이미지가 경기 이동 로직으로 움직인다.
- 실제 Android/iOS 기기의 성능·메모리·터치·노치 검증은 수행하지 않았다.

검증
- Scene_All3D / Scene_2D_3D / Scene_All2D: 각 14개 경기·필살기 검사 통과. 영상 재생, 일시정지, 건너뛰기, 복귀, 영상 중 재시작과 경기 결과 일치 확인.
- 두 2D 씬: 각 96개 달리기 검사 통과. 16개 적용 뷰, 정지 이미지 대체, 일시정지, 배속, 일정한 캔버스 크기 확인.
- 두 2D 씬의 4구간 × 3구도 실제 화면 검수. 하이브리드 사이드 카메라가 관중석에 가려지던 문제 수정 후 재검사.
- 모든 적용 시트는 검수한 파일과 Unity 파일의 해시를 비교했다. 선택 프레임의 경계 잘림 0 확인.
- WebGL 일반 Brotli 최종 빌드 성공: 07:21:31 완료, 오류 0·경고 0, 약 175 MB. 실제 생성된 빌드를 브라우저에서 실행 검증했다.
- 실제 브라우저의 Scene_All2D에서 주행·달리기, 자동/수동 3구도, 공통 메뉴 일시정지·재개, 재시작·배속, 여우 영상 재생·정지·재개·연출 생략·경기 복귀와 결과 화면을 확인했다. 영상 정지 중 두 화면의 SHA256도 동일했다.
- 데스크톱 1280×900에서 게임 영역 506×900의 중앙 세로 배치, 모바일 비율 약 394×852에서 전체 높이 확장과 HUD 표시를 확인했다. 이 검사는 데스크톱 브라우저의 화면 크기 변경이며 실제 휴대전화 검증은 아니다.
- 웹 결과는 에디터와 동일한 순서 4→5→3→6→2→1이며 우승 기록 58.366초, 내 주자 3위·59.136초를 확인했다.
- 재진입 후 첫 조작 없이 경기를 두었을 때 발소리의 PlayOneShot이 쌓여 오디오 채널 부족 경고가 발생했다. 발소리 8개·강조 효과음 4개의 AudioSource를 재사용하도록 수정하고 108초 이상 무조작 상태에서 한 경기를 끝까지 실행하여 경고·오류 0을 확인했다.
- 공통 결과 패널에서 배경 뒤에 가려지던 우승 문구와 다시 달리기 버튼의 부모 계층을 수정했다. 세 씬에서 실제 UI 레이캐스트가 버튼에 닿고 클릭으로 새 경기 카운트다운이 시작됨을 확인했다. 최종 웹 빌드에서도 화면에 보이는 버튼을 직접 클릭하여 카운트다운으로 복귀함을 확인했다.
- WebGL 검수 빌드에는 세 씬이 들어 있으며 첫 진입 씬은 All2D다. 하이브리드·All3D의 기능 검증은 에디터에서 수행했다. 모든 씬과 검수용 자산이 포함된 프로토타입으로 모바일 용량·메모리 최적화는 별도다.
