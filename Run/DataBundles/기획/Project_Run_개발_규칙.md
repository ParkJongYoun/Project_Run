# Project Run 개발 규칙

- 확정일: 2026-10-15
- 대상: Unity WebGL 기반 H5 캐릭터 레이스 게임
- 적용 범위: 신규 코드·에셋과 기존 게임 기능을 수정하는 작업

기존 Project WG에서 선정한 1~15번 규칙에 Project Run의 레이스 구성과 사용자가 지정한 변수 이름을 반영한다. 2026-10-17부터 타이틀과 타원 경기 화면은 가로형 1280×720 설계를 사용한다. 현재 개발은 `Assets/Resources`, JSON 테이블, 브라우저 저장을 사용한다. 경기 계산과 화면 표현을 분리하여 카메라 전환·배속·건너뛰기를 지원한다.

이 문서는 개발 기준이다. 아래의 폴더·클래스 예시는 해당 기능을 만들 때 사용하며, 기능이 이미 구현되었다는 의미는 아니다.

## 1 공통 관리자와 씬별 시스템

- `Mgr_`는 씬을 넘어 유지되는 공통 기능을 담당하고 `Assets/Scripts/Core`에 둔다. 예: `Mgr_Game`, `Mgr_Scene`, `Mgr_UI`, `Mgr_Table`, `Mgr_User`, `Mgr_Bundle`, `Mgr_Event`, `Mgr_Sound`.
- `Sys_`는 해당 씬에서 필요한 기능을 담당하고 기능별 폴더에 둔다. 예: `Sys_Race`, `Sys_RaceCamera`, `Sys_RacePresentation`.
- 하이어라키에서 영속 관리자는 `[Managers]`, 씬별 시스템은 `[Systems]` 아래에 모은다. 씬을 나갈 때 시스템과 씬 참조를 정리한다.
- 공통 초기화는 중복 호출에 안전하게 만들고, 초기화·사용·정리 책임을 명확히 한다.
- 개별 주자나 UI 항목은 일반 객체·컴포넌트로 만든다. 모든 클래스를 싱글톤으로 만들지 않는다.
- 경기 계산은 주자 전체의 상태를 관리하고, 카메라와 UI·연출은 그 상태를 읽어 표현한다. 경기 계산이 카메라나 패널 객체를 직접 조작하지 않게 한다.

## 2 코드 이름

변수의 `ins_`와 선행 `_` 접두어를 없앤다. 인스펙터 노출 여부를 먼저 판단한다.

| 대상 | 규칙 | 예시 |
|---|---|---|
| 인스펙터 노출 필드 | 대문자로 시작 | `[SerializeField] private float FirePower;` |
| public 필드·프로퍼티 | 대문자로 시작 | `public float MoveSpeed;` |
| 그 외 private 필드 | 소문자로 시작 | `private float raceTimer;` |
| 지역변수·매개변수 | 소문자로 시작 | `runnerId`, `remainingDistance` |
| 메서드 | 대문자로 시작 | `StartRace()`, `RefreshRank()` |

- 매개변수에 `in`·`out` 같은 이름 접두어를 강제하지 않는다. C#의 `in`·`out` 키워드 사용과는 별개다.
- 역할별 클래스 접두어는 유지한다: `Mgr_`, `Sys_`, `UIPanel_`, `UIItem_`, `UISlot_`, `Data_`, `Table_`, `Define_`, `E_`.
- 인스펙터 편집만 필요하면 `[SerializeField] private`을 사용한다. 대문자 이름을 쓰기 위해 접근 범위를 public으로 바꾸지 않는다.
- 인스펙터 항목에는 필요한 설명과 그룹을 붙인다. 기존 직렬화 필드를 바꿀 때는 저장된 참조·값을 유지하도록 이전 이름을 연결한다.

## 3 스크립트 폴더

`Assets/Scripts` 아래에서 역할과 기능을 구분한다. 폴더는 해당 기능을 만들 때 생성한다.

| 폴더 | 내용 |
|---|---|
| `Core` | 공통 관리자와 공통 베이스 |
| `Game/Race/Simulation` | 경기 진행·순위·완주·스킬 판정 |
| `Game/Race/Runner` | 주자 객체와 모델·애니메이션 표현 |
| `Game/Race/Camera` | 구도·추적 대상·카메라 전환 |
| `Game/Race/Presentation` | 스킬 연출·중계·승리 연출 |
| `Game/UI/Common` | 패널·항목 베이스와 공통 슬롯 |
| `Game/UI/Lobby`, `Race`, `Result` | 각 화면의 패널과 UI 항목 |
| `Data/Tables` | 게임용 테이블 클래스 |
| `Data/GameDB` | 유저 데이터와 저장용 구조 |
| `Util` | 공통 도우미 |
| `Editor` | Excel 변환·데이터 확인 등 에디터 도구 |
| `Test` | 개발용 테스트 진입점과 검증 도구 |

실행 중 사용하는 코드에서 `Editor` 코드를 참조하지 않는다. 다른 기능의 내부 구현에 직접 접근하는 대신 필요한 데이터·메서드를 통해 연결한다.

## 4 원본과 게임 리소스

- 작업 원본·기획 자료는 프로젝트 루트의 `DataBundles`에 둔다. Excel 원본은 `DataBundles/테이블`에 둔다.
- 2026-10-18부터 작업 산출물은 `DataBundles` 안에서 용도·대상을 알 수 있는 **한글 폴더명과 한글 파일명**으로 정리한다. 예: `아트/카프라_튜토리얼_안내인/카프라_왼손안내.png`. 날짜·순번·확장자는 필요에 따라 붙인다.
- Unity의 `Assets`로 넣는 폴더와 파일은 기존 프로젝트 규칙에 맞는 **영문 이름**을 사용한다. 한글 작업 원본을 보존하고 필요한 최종본을 영어 이름으로 복사·연결한다. 외부 도구가 요구하는 고정 파일명·포맷·백업 내부의 Unity 원본 경로는 호환성을 유지한다.
- 산출물은 개별 파일로 제공하며, 사용자가 명시적으로 요청하지 않으면 ZIP 등 압축 파일을 만들지 않는다. 최종 전달 폴더에는 확정된 결과만 남기고, 해당 작업에서 만든 불필요한 중간 시안·임시 산출물·중복 압축본을 정리한다. 재생성·검증에 필요한 원본과 기록은 최종본과 구분하여 한글 작업 폴더에 보관하고, 다른 작업의 파일을 임의로 삭제하지 않는다.
- 다른 채팅에서 작업 중인 폴더·파일과 그 상위 경로는 이름 변경·이동·정리 대상에서 제외한다. 기존 자료의 경로를 바꿀 때는 관련 도구와 문서의 참조를 함께 갱신하고, 최종 저장 경로를 사용자에게 안내한다.
- 아트 작업 에셋은 `Assets/ArtBundles`에서 관리한다. 폴더 이름만으로 AssetBundle 배포를 사용한다는 의미는 아니다.
- 현재 런타임 로드 리소스는 `Assets/Resources`를 사용한다. 필요한 에셋을 선택해 등록한다.
- 외부 패키지·플러그인과 프로젝트 자체 제작물을 구분한다. 기존 `Assets/OldAsset`의 원본과 참조를 보존한다.

| 런타임 폴더 | 내용 |
|---|---|
| `Assets/Resources/Prefabs` | 게임용·모델 전시용·UI 프리팹 |
| `Assets/Resources/UI` | UI 이미지와 아이콘 |
| `Assets/Resources/Audio` | BGM·효과음 |
| `Assets/Resources/Tables` | 게임용 JSON 테이블 |

현재 단계에서는 기존 Unity 리소스 로드 방식으로 개발한다. 실제 배포 용량이나 첫 로딩이 문제가 될 때 필요한 묶음의 다운로드 분리를 검토한다.

### 카툰 외형 적용의 재사용 기준

- 2026-10-17 사용자 요청으로 미노타우로스와 6종 외형 경기장에서 사용한 방식을 [project-run-cartoon-look 스킬](../../../ProjectSupport/Skills/project-run-cartoon-look/SKILL.md)에 기록했다. “카툰풍으로 바꿔줘”, “미노처럼 바꿔줘” 요청은 이 절차를 기본으로 사용하며 최신 대상·스타일 지시를 우선한다.
- 기본 작업은 원본 UV와 캐릭터 특징을 유지한 알베도 편집, 승인된 셰이더·재질·윤곽선 적용, 대상 씬에 필요한 조명 보정이다. 카툰 캐릭터는 원본과 별개의 Regular 프리팹과 전용 리소스로 만든다. 원본 재질을 연결하거나 수정하지 않고 새 카툰 재질·텍스처를 사용한다. Variant나 씬 재질 오버라이드만으로 끝내지 않는다.
- 모델·리깅·애니메이션·스탯·이동속도·크기·무기 표시는 별도 요청 범위다. 모든 기존 에셋의 자동 변환이나 프로젝트 전체 렌더링 설정 변경을 뜻하지 않는다.
- 재질·조명 수치와 검증 사례는 스킬의 참조 문서에서 관리한다. 기존 사례의 완료 기록과 새 대상의 검증 결과를 구분한다.
- 2026-10-20 신규 미노 재수정: 카툰화는 원본의 얼굴·형태·디테일 품질을 보존한다. UV가 잘게 나뉜 원본의 재생성 텍스처가 얼룩·해상도 손실을 만들면 채택하지 않고, 원본 알베도·노멀맵의 전용 복사본과 대상별 셰이더 보정을 사용할 수 있다. 실제 파일/임포트 크기·동일 구도 비교·실시간 동작을 검증하고, 거절된 시안·기술 검증·사용자 외형 승인을 구분한다. 상세 증거는 스킬의 신규 미노 품질 복구 사례에 기록한다.
- 2026-10-17 추가 요청으로 카툰 6종을 `Assets/Resources/Prefabs/Race/CartoonMonsters/P_Runner_Cartoon_{ID}.prefab`의 독립 프리팹으로 분리했다. 메시·아바타·애니메이션·텍스처·재질·초상화는 `Assets/ArtBundles/Characters/CartoonMonsters`의 전용 리소스를 사용한다. `Scene_OvalToon`은 이 프리팹만 사용하며 원본/Toon/Outlined 재질 목록과 외형 전환 기능을 유지하지 않는다. 기존 타원 경기장·원본 에셋·미노 단독 비교 씬은 보존한다.
- 이후 같은 날 요청으로 카툰 경기 두 씬의 마타·오크를 기수 없는 자이언트 포링·호랑이 에드가의 독립 카툰 프리팹으로 교체한다. 원본 탈것 모델과 동작을 복제하고 전용 카툰 재질·텍스처·초상화를 연결한다. 기존 캐릭터 조합의 두 씬에는 이 교체를 적용하지 않는다.

## 5 화면 방향과 해상도

- 2026-10-18 심사 데모의 `Scene_Title`, `Scene_Lobby`, `Scene_OvalToon`, `Scene_2D` 화면은 가로 1280×720·`CanvasScaler.Expand`·Safe Area를 사용한다. 아래 2026-10-17 변경의 기존 비교 씬은 보존하며, 새 데모 UI의 적용 범위를 별도로 확장한 것이다.
- 2026-10-17 사용자 요청으로 `Scene_Title`과 `Scene_Oval`의 타이틀·레이스·메뉴·결과·스킬 영상은 **가로형**으로 전환한다. 그 외 비교·테스트 씬과 아직 제작하지 않은 화면의 방향은 이번 변경으로 일괄 확정하지 않는다.
- 위 두 씬의 UI 설계 기준은 **1280×720**이며 `CanvasScaler`의 `Scale With Screen Size`와 `Expand`를 사용한다. 이 값은 실제 렌더링 픽셀 수와 구분한다. 기존 비교·테스트 씬의 720×1280 기준은 이번 변경 범위에서 제외한다.
- 기준 영역에 진행도·내 주자 순위·주요 조작처럼 필수 정보를 배치한다. 넓은 화면에서는 캐릭터의 가독성을 유지하며 경기 표시 영역을 좌우로 확장한다. 좁은 창에서는 기준 UI 전체가 들어가게 축척한다.
- 상·하단 고정 UI는 앵커와 Safe Area에 맞춰 배치한다. 배경과 경기 화면은 필요한 범위까지 확장할 수 있다.
- 2026-10-18 화면 잘림 수정 요청으로 데모·테스트 웹 빌드의 공통 템플릿은 게임 표시 영역을 **16:9**로 유지하며 브라우저의 사용 가능한 영역 안에 최대 크기로 맞춘다. 21:9처럼 넓은 창에서는 좌우 여백을, 더 좁은 창에서는 상하 여백을 두고 화면 전체를 중앙에 표시한다. 위의 넓은 화면 좌우 확장 기준보다 이 웹 표시 기준을 우선한다. Safe Area는 게임 영역 바깥에서 확보하고 창 크기·브라우저 전체화면 전환에도 비율을 유지한다. 세로 브라우저에서는 가로 회전 안내를 제공하며 화면 회전을 강제하지 않는다.
- 기존 Windows 창 크기 강제 조절과 고정 9:16 레터박스 코드를 그대로 가져오지 않는다. 웹 표시 영역과 화면비 대응은 브라우저 기준으로 구현한다.
- 현재 웹 빌드의 기본 Quality는 에디터와 같은 **`PC`**이며 `Assets/Settings/PC_RPAsset.asset`를 사용한다. 웹 빌드나 빌드 도구에서 `Mobile` 품질로 자동 하향하지 않는다.
- 현재는 같은 씬·카메라·화면비에서 에디터와 웹의 셰이더·색감·그림자·선명도가 동일하게 보이는 것을 우선한다. 이 기준은 작업 목표이며 모든 기기에서 시각적 일치가 검증되었다는 의미는 아니다.
- 성능 최적화를 위한 품질·렌더링 해상도·배율 조정은 위 시각 기준을 확인한 뒤, 목표 모바일 브라우저의 글자 가독성과 실제 실행 성능을 측정하여 별도로 진행한다.

## 6 캔버스와 표시 순서

공통 루트 이름은 `UICanvas_Root`로 한다. 패널의 레이어는 `E_CanvasLayer`로 지정하며 `Mgr_UI`가 해당 위치에 붙인다. 입력용 `EventSystem`은 중복 생성하지 않는다.

| 레이어 | 기본 정렬 순서 | 역할 |
|---|---|---|
| `World` | 0 | 주자에 연결되는 이름표·표시 |
| `Game` | 100 | 진행도·순위·관전 조작 HUD |
| `Panel` | 200 | 편성·정보·결과 같은 일반 화면 |
| `Cutscene` | 300 | 스킬·승리 등 화면 연출 |
| `Popup` | 400 | 메뉴·일시정지·확인 창 |
| `System` | 500 | 로딩·오류 등 최상단 안내 |

- 캔버스 객체 이름은 `Canvas_Game`처럼 레이어와 연결한다.
- 연출 중에도 필요한 메뉴·시스템 안내가 가려지지 않게 한다. 배경이나 장식 UI는 불필요하게 입력을 가로채지 않는다.
- `PopupSub`는 실제로 다단계 팝업이 필요할 때 추가한다. 위의 계층을 화면 요소마다 별도 Canvas를 만드는 규칙으로 확대하지 않는다.

## 7 UI 패널

- 패널은 `UIPanel_Base`를 공통 기반으로 사용한다. 클래스·프리팹은 `UIPanel_RaceHUD`, 등록 enum은 `E_PanelType.RaceHUD`처럼 이름을 맞춘다.
- 패널 프리팹은 `Resources/Prefabs/UI/Panel`, 공통 슬롯은 `Resources/Prefabs/UI/Slot`에 둔다.
- 열기·닫기는 `Mgr_UI`로 모으고 `OnOpen`에서 표시 준비, `OnClose`에서 구독·작업·표시 상태를 정리한다.
- 재사용 패널은 닫을 때 비활성화하고, 일회용은 정리 후 제거한다. 재사용 시 데이터와 콜백을 다시 연결할 수 있게 한다.
- 레이스 HUD는 진행도, 팀 순위, 스킬 알림, 중계 문구, 관전 조작으로 역할을 나눈다.
- 카메라 밖 주자의 순위도 경기 데이터에서 읽어 표시한다. 화면에 보이는 모델만으로 전체 순위를 계산하지 않는다.

### UI 프리팹 제작 방식과 기준 예제

- SGL에서 사용자가 만든 `UIPanel_Test.prefab`을 구조 참고용 기본형으로 가져왔다. 위치는 `Assets/Resources/Prefabs/UI/Panel/UIPanel_Test.prefab`이다. 새 UI를 만들거나 계층을 수정할 때 이 프리팹의 최신 구조를 먼저 확인한다.
- 내부 오브젝트 이름은 가능한 한 소문자와 `_`를 사용한다. `bg_`는 배경, `img_`는 이미지, `txt_`는 텍스트, `obj_`는 기본 묶음, `group_`은 여러 묶음을 포함하는 큰 화면·기능 영역, `popup_`은 기존 화면 위에 새로 여는 창에 사용한다.
- 입력 요소는 `btn_`, `slider_`, `input_`, `dropdown_`, `toggle_`, `scroll_`, `scrollbar_`처럼 실제 기능에 맞는 접두어를 사용한다. 이름 예시는 필수 요소나 계층을 추가하라는 뜻이 아니다.
- 프리팹 파일명·루트 식별자와 클래스의 `UIPanel_`, `UIItem_`, `UISlot_` 규칙은 유지한다. 공통 루트 `UICanvas_Root`와 레이어 `Canvas_Game` 등의 이름은 6번 규칙을 따른다. 내부 이름 규칙을 기존 에셋 전체 재명명으로 확대하지 않는다.
- 프레임·테두리와 내부 배경은 별도 이미지 에셋과 표시 레이어로 구성해 색·투명도·선택 상태를 독립적으로 조절한다. 필요하면 프레임에 9-slice를 적용한다. 한 이미지를 두 Image에 연결하는 것은 에셋 분리가 아니다. 합본 예외가 필요하면 대상과 이유를 설명하고 명시적으로 합의한다.
- UI 시안은 실제 게임 화면의 배경·패널·버튼·문구·장식까지 포함한 외형을 기본으로 한다. 사용자가 러프만 요청하면 그 범위를 따른다. 시안 승인과 실제 파츠 제작·Unity 연결·기능 구현은 구분하고, 명시적으로 요청한 적용은 다시 승인받지 않는다.
- 예제는 SGL의 계층·배치·활성 상태·GUID와 기존 uGUI Text를 보존한 제작 참고 자료다. SGL용 제목·배경·문구를 Project Run의 확정 디자인으로 채택한 것이 아니다. 예제 자체에는 Canvas, EventSystem, 패널 동작 스크립트가 없으며 게임용으로 사용할 때는 5~7번의 씬별 해상도 기준, Safe Area, 캔버스 계층과 패널 수명을 적용한다.
- 원본: `D:/Project_SGL/Assets/Resources/Prefabs/UI/Panels/UIPanel_Test.prefab`, 제작 방식 출처: SGL `AGENTS.md`의 UI 프리팹 구조·이름 규칙 및 `ProjectSupport/Skills/sgl-ui-design-workflow/SKILL.md`. 의존 이미지·폰트는 `Assets/ArtBundles/UI/SGLReference`에서 관리하며 원본 프로젝트를 수정하지 않는다.

## 8 프리팹 역할과 기준점

- 2026-10-16 확정: 경기에는 몬스터만 출전한다. 기수 캐릭터는 경기용 프리팹과 씬 배치에서 제외하고, 프로필·이름표·클로즈업 기준점은 몬스터에 연결한다. 기존 기수 원본 에셋은 보존한다.
- `P_`는 게임용 프리팹, `M_`는 모델·애니메이션 프리팹, `V_`는 UI 전시용 프리팹을 나타낸다. 예: `P_Runner_001`, `M_Runner_001`, `V_Runner_001`.
- UI는 별도의 `UIPanel_`, `UIItem_`, `UISlot_` 이름 규칙을 사용한다.
- 프로젝트에서 만드는 프리팹 루트의 위치·회전은 기본값, 스케일은 1을 기준으로 한다. 모델 크기·방향·높이 보정은 자식 루트에서 처리한다.
- 게임용 주자 프리팹은 경기 데이터를 모델과 애니메이션에 표현한다. UI 전시용 프리팹은 경기 계산 없이 사용할 수 있게 한다.
- 카메라 추적·얼굴 클로즈업·이름표 위치에 필요한 기준점을 공통 이름으로 둔다. 모델마다 달라지는 위치는 프리팹에서 조정한다.
- 화면에서 사라졌다는 이유로 경기 계산을 중지하지 않는다. 표시 최적화와 경기 진행은 별도로 다룬다.

## 9 반복 UI와 알림 재사용

- 반복 목록은 `UIItem_Base<T>`와 공통 도우미로 초기화·데이터 연결·리셋을 처리한다.
- 필요한 수가 늘 때만 항목을 추가 생성하고, 남는 항목은 상태를 비운 뒤 비활성화한다.
- 순위 슬롯은 데이터와 순서를 갱신하며, 순위가 바뀔 때마다 전체 UI를 다시 생성하지 않는다.
- 스킬 알림과 중계 문구는 표시 개수·유지 시간·우선순위를 설정할 수 있게 한다. 구체적인 수치는 화면 검증으로 정한다.
- 건너뛰기·경기 종료 시 오래된 알림을 비우고, 이전 경기의 콜백이나 표시 상태가 다음 경기로 남지 않게 한다.

- 경기 안에서는 준비 → 출발 → 주행 → 완주 → 결과 단계를 명시적으로 관리한다. 장면 연출이 바뀌었다고 경기 상태를 임의로 변경하지 않는다.
- 정식 진입과 개발용 직접 실행은 같은 경기 초기화·종료 정리 함수를 사용한다.
- 경기 계산은 거리·순위·스킬·완주 판정을 담당한다. 카메라나 애니메이션의 재생 완료가 판정의 기준이 되지 않게 한다.
- 배속과 건너뛰기도 같은 경기 판정 규칙을 사용한다. 결과는 경기 계산에서 만들고, 건너뛰기 시 생략하는 화면 연출과 구분한다.

- 경로는 `DataBundles/테이블`, `Assets/Resources/Tables`, `Assets/Scripts/Data/Tables`를 사용한다. Unity 테이블 이름은 `Table_`로 시작한다.
- Excel 해석과 변환 도구는 에디터에서 실행한다. 게임 실행 중에는 JSON을 읽어 타입이 있는 데이터로 변환한다.
- 필요한 테이블을 로드·파싱한 뒤 ID 기준으로 메모리에서 조회한다. 스탯 조회마다 JSON을 다시 읽거나 파싱하지 않는다.
- 주자 기본 능력치·코스·스킬 같은 설정 데이터와 경기 중 거리·순위·체력 같은 상태 데이터를 분리한다.
- 자동 생성 파일은 원본·생성 도구와 일치하게 유지한다. 변환 시 필수 값·타입·중복 ID·참조 ID를 확인한다.
- 현재는 빌드에 포함한 JSON을 사용한다. 운영 중 외부 데이터 교체는 필요해질 때 버전 관리와 함께 추가한다.

## 12 이벤트와 작업 정리

- 공통 이벤트 창구는 `Mgr_Event`로 모으고, 전역 유지 구독과 씬 한정 구독을 구분한다.
- 이벤트가 필요한 정보를 함께 전달하도록 한다. 예: 스킬 발동 시 주자 ID, 스킬 ID, 발생 경기 시간.
- 경기 계산에서 발생한 사건을 UI·카메라·사운드가 각각 처리한다. 지속적으로 필요한 거리·진행도는 경기 상태를 조회한다.
- 구독한 객체가 해제를 책임지고, 씬 종료 시 씬 한정 구독을 정리한다.
- 패널 종료·객체 제거·씬 전환 시 관련 비동기 작업·트윈·콜백을 종료한다. 이미 끝난 경기나 닫힌 UI에 후속 작업이 적용되지 않게 한다.

## 13 리소스 경로와 수명

- 현재 로드 창구는 `Mgr_Bundle`로 공통화하고 내부에서 `Resources`를 사용한다. 이름이 Bundle이어도 원격 AssetBundle 도입을 뜻하지 않는다.
- 반복 사용하는 경로는 `Define_Path` 등 한 곳에서 관리한다. 실제 프리팹·테이블 경로와 일치시킨다.
- 로드한 원본 에셋의 캐시와 생성된 게임 객체의 풀을 구분한다.
- 공통 에셋, 경기 중 에셋, 일시적 연출용 객체의 사용 범위를 정한다. 경기 종료 시 경기 전용 객체·참조·캐시를 정리하되 다른 화면이 사용하는 자원은 유지한다.
- 누락된 에셋은 요청한 경로·ID를 로그로 남겨 원인을 찾을 수 있게 한다.

## 14 개발용 유저 데이터 저장

- 현재는 서버 연결 없이 **같은 브라우저에서 이어하기 위한 개발용 저장**을 구현한다.
- `Mgr_User`가 유저 데이터를 관리하고, `Data_UserSave` 같은 별도 구조가 저장 형식을 담당한다. 작은 환경설정은 `PlayerPrefs`, 구조화한 진행 데이터는 JSON 저장을 기본으로 한다.
- 웹에서 JSON 파일은 `Application.persistentDataPath` 기반 저장을 사용하고 브라우저 저장소까지 반영되는지 확인한다. Windows용 파일 저장 구현을 그대로 복사하지 않는다.
- 설정, 육성·보유 데이터, 필요한 경기 임시 상태를 구분하고 저장 버전을 기록한다. 손상되거나 지원하지 않는 버전은 오류를 알리고 복구·초기화 경로를 제공한다.
- 중요한 진행 변경 시 저장한다. 탭 종료 시점에만 저장을 의존하지 않는다. 웹 빌드에서 새로고침 후 복원까지 확인한다.
- 브라우저 저장은 계정 연동 저장을 대신하지 않는다. 로그인·기기 간 이어하기가 필요해질 때 서버 저장을 연결할 수 있도록 게임 데이터와 저장 처리를 분리한다.
- 경기 중 새로고침 시 재시작할지 중간 복원할지는 해당 기능 구현 시 정한다. 중간 경기 복원을 이미 지원한다고 가정하지 않는다.

## 16 Git 커밋과 푸시

- 사용자가 Git에 올려 달라고 요청하면 변경 내용을 검토하고 작업별로 묶어 각각 커밋한다. 서로 다른 작업을 한 커밋에 몰아넣지 않는다. 같은 작업의 코드·에셋·메타 파일·검증 자료는 함께 묶는다.
- 커밋 메시지는 한글로 작성한다. 제목 한 줄은 핵심 변경과 목적을 알아볼 수 있도록 너무 길거나 짧지 않은 한 문장으로 요약하고, 빈 줄 뒤에 요약 불릿 2~3개를 붙인다. 각 불릿은 한 줄로 쓰며 세부 구현 설명이나 근거는 넣지 않는다.
- 커밋·푸시는 사용자가 요청했을 때 수행한다. “커밋해줘” 또는 Git에 올려 달라는 요청은 작업별 커밋과 푸시까지 포함한다.
- 커밋 전 변경 내용과 관련 검증, 포함할 파일 및 원격 브랜치 상태를 확인한다. 문제가 없으면 커밋 후 푸시까지 진행하고 결과를 보고한다.
- 검증 실패나 충돌 등 문제가 있으면 원인과 완료한 범위를 보고한다. 실제로 수행한 검증과 기존 검증 기록을 구분한다.

메시지 형식은 2026-10-19 SGL 프로젝트의 `CLAUDE.md` 내 “커밋 메시지” 규칙에서 가져왔으며, 작업별 분리와 요청 후 푸시는 SGL `AGENTS.md` 및 Run의 기존 기준을 따른다. 개인 전역 설정 없이 이 저장소의 공용 규칙으로 적용한다.

```text
로비 재진입 시 선택한 몬스터가 바뀌던 문제 수정

- 몬스터 조회와 경기 출전 선택을 독립적으로 유지
- 일반 로비 재진입 시 현재 실행의 선택 보존
```

## 참고와 적용 범위

[우마무스메 세로형 레이스 영상 분석](우마무스메_세로형_레이스_영상_분석.md)은 카메라·UI·연출의 참고 자료다. 영상의 팀 인원수와 상세 경기 규칙을 그대로 확정하지 않으며, 수동 스킬 조작 같은 별도 기능도 채택 여부를 따로 정한다.

기존 에셋과 외부 패키지는 참조를 보존한다. 이름 규칙은 신규 작업과 수정 대상에 적용하며, 전체 프로젝트를 한 번에 재명명하는 작업으로 확대하지 않는다.

현재 반영 범위는 개발 규칙과 UI 구조 참고 예제의 등록이다. 예제는 Unity 임포트와 참조 누락 검사를 마쳤으며 게임 동작 연결은 별도다. 각 관리자·시스템·도구는 해당 기능을 구현할 때 이 규칙에 맞춰 추가한다.
