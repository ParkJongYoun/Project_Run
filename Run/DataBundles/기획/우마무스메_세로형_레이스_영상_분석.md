# 우마무스메 세로형 레이스 영상 분석

- 작성일: 2026-10-15
- 대상 프로젝트: Project Run / H5(HTML5) 웹 경마·캐릭터 레이스 게임
- 목적: 세로형 화면의 적합성을 검토하고 레이스 카메라, UI, 연출의 참고 방향을 기록한다.
- 문서 상태: 참고 영상 분석 및 설계 권장안. 최종 확정 사양은 아니다.

## 1. 참고 영상과 확인 범위

- 영상 제목: [우마무스메] 5차 CLASSIC 1R 01 (세로화면)
- 영상 주소: <https://www.youtube.com/watch?v=13XFXelPRvI>
- 영상 길이: 4분 13초
- 접속 상태: 브라우저에서 접속 및 재생 확인.
- 확인 방법: 출전 준비, 출발, 주행, 스킬 연출, 막판 경쟁, 결과 구간으로 이동하면서 화면을 확인했다.
- 분석 범위: 화면에서 확인한 카메라 구도, UI 배치, 시각적 연출을 중심으로 한다. 내부 경기 계산, 스킬 판정, 카메라 선택 알고리즘은 확인하지 않았다.

## 2. 결론

**이 영상처럼 캐릭터 육성·편성과 레이스 관전이 중심인 게임이라면 세로형을 추천한다.**

중앙 화면은 일부 주자와 중요한 경쟁 장면을 크게 보여주고, 상단 진행도와 하단 팀 순위가 전체 경기 상황을 보완한다. 모든 주자를 한 화면에 계속 표시하지 않아도 경기 흐름을 전달할 수 있는 구성이다.

프로젝트가 원하는 세로형 방향을 유지하면서 육성부터 레이스까지 화면 방향을 통일하는 것이 적합하다. 플레이어가 직접 좌우 이동과 진로를 조작하는 방식까지 도입할 경우에는 주변 주자의 가시성을 별도로 검토해야 한다.

## 4. 레이스 UI의 역할 분담

| 화면 영역 | 영상에서 확인한 구성 | 역할 |
|---|---|---|
| 상단 | START–GOAL 진행 바와 주자 표시 | 전체 경기 진행과 주자 분포를 요약한다. |
| 상단 아래 | 스킬 발동 알림 | 경기 중 발생하는 변화를 전달한다. |
| 중앙 | 카메라가 선택한 주자와 경쟁 장면 | 캐릭터의 움직임과 레이스 연출을 보여준다. |
| 하단 | 내 팀 3명의 초상화와 현재 순위 | 카메라 밖에 있는 팀원의 상황도 확인하게 한다. |
| 하단 중계 영역 | 중계·해설 문구 | 화면만으로 파악하기 어려운 경기 상황을 보완한다. |
| 최하단 | 카메라, 배속, 건너뛰기, 메뉴 등 관전 관련 기능 | 관전과 진행 방식을 조절한다. |

**핵심은 화면에 보이지 않는 주자의 상황도 UI로 계속 전달하는 것이다.** 중앙 화면은 경기의 재미를, 고정 UI는 상황 파악을 맡는다.

확인한 레이스 화면은 관전 중심의 구성이다. 앞서 논의한 수동 스킬 버튼은 프로젝트에서 선택할 수 있는 별도의 설계안이며, 이 영상에서 확인한 기능으로 간주하지 않는다.

## 5. 카메라와 연출에서 참고할 점

후방 대각선 추적 카메라 하나를 기본으로 고정할 필요는 없다. 영상에서는 높은 위치의 대열 구도, 정면·측면 주행 구도, 얼굴 클로즈업, 막판 경쟁 구도를 확인할 수 있다.

프로젝트에는 다음과 같은 상황별 구성을 권장한다.

1. **출발:** 전체 대열을 보여주어 참가자와 경기 시작을 인지시킨다.
2. **일반 주행:** 정면 또는 측면 추적으로 주요 주자를 보여준다.
3. **중요한 변화:** 스킬 알림과 짧은 클로즈업으로 변화가 발생했음을 강조한다.
4. **막판 경쟁:** 선두 또는 내 팀의 중요한 경쟁 장면을 보여준다.
5. **경기 종료:** 승리 캐릭터와 팀 결과를 강조한다.

위 순서는 영상 관찰을 바탕으로 한 프로젝트 적용 제안이다. 원작의 내부 카메라 전환 조건을 확인한 것은 아니다.

## 6. 세로형의 한계와 보완 방향

- 측면 주행 구도에서는 앞뒤 주자가 화면 밖으로 빠지기 쉽다.
- 여러 주자가 겹치면 캐릭터 구분과 정확한 간격 파악이 어려울 수 있다.
- 전체 대열을 한 화면에 담으면 개별 캐릭터가 작아진다.
- 스킬 알림과 중계 문구가 많아지면 레이스 화면을 가릴 수 있다.

프로젝트에서는 내 캐릭터 표시와 팀 순위를 우선 명확하게 제공한다. 필요하면 순위 변화와 선두와의 거리를 추가해 카메라 밖의 상황을 보완한다. 알림은 표시 개수와 노출 시간을 제한해 주요 주자를 가리지 않도록 설계한다.

## 7. Project Run 적용 권장안

| 항목 | 권장 방향 |
|---|---|
| 화면 방향 | 육성·편성·레이스·결과를 세로형으로 통일한다. |
| 기준 해상도 | UI 설계 기준을 720×1280으로 시작한다. |
| 긴 모바일 화면 | 캐릭터의 가독성을 유지하면서 레이스 표시 영역을 위아래로 확장한다. |
| 레이스 카메라 | 전체 대열, 측면 추적, 정면 경쟁, 스킬 연출을 상황에 따라 전환한다. |
| 항상 확인할 정보 | 내 팀 순위, 경기 진행도, 중요한 스킬 발동을 우선 제공한다. |
| PC 브라우저 | 중앙에 세로형 게임 화면을 배치하고 좌우 공간은 배경 등으로 처리한다. |
| 첫 구현 우선순위 | 달리는 캐릭터, 카메라 전환, 순위 UI를 먼저 구현해 관전 재미를 확인한다. |

영상의 표시 구도는 9:16보다 긴 세로 비율이다. 정확한 원본 녹화 해상도는 확인하지 않았으므로 영상의 픽셀 크기를 프로젝트 규격으로 사용하지 않는다.

**720×1280 안에 반드시 보여야 할 정보를 정하고, 긴 화면에서 경기 영역을 더 보여주는 방식**을 권장한다. 이 값은 UI와 화면 배치의 기준이며 실제 렌더링 해상도는 기기 성능에 맞춰 별도로 조절한다.

영상만으로 H5 환경의 성능을 판단할 수는 없다. 초기 프로토타입에서 목표 모바일 브라우저의 캐릭터 수, 카메라 연출, UI 가독성과 실행 성능을 함께 확인한다.
